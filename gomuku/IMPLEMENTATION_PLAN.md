# 15x15 五子棋神经网络 AI 实现计划

## 1. 项目目标

构建一个基于神经网络与自对弈训练的 15x15 五子棋 AI（黑先白后、无禁手），并提供一个小型应用，支持加载训练好的模型让用户与 AI 对战（可选择执黑或执白）。

---

## 2. 阶段划分总览

1. **阶段 A：基础工程与规则环境**
2. **阶段 B：模型与推理链路**
3. **阶段 C：自对弈训练闭环**
4. **阶段 D：评估、模型管理与对战应用**
5. **阶段 E：优化与发布**

每个阶段都应满足“可运行 + 可验证”的最小闭环，再进入下一阶段。

---

## 3. 技术栈建议

- 语言：Python 3.10+
- 深度学习框架：PyTorch
- 数值计算：NumPy
- 前端（两选一）：
  - 方案 1：`pygame`（实现快，适合桌面小工具）
  - 方案 2：`FastAPI + React`（可扩展，适合后续网页部署）
- 配置管理：YAML 或 JSON
- 模型管理：本地 `checkpoints/` + 最佳模型软链接（或记录文件）

## 5. 详细阶段计划

## 阶段 A：基础工程与规则环境（预计 2-4 天）

### A1. 初始化工程
- 创建目录结构与 Python 虚拟环境
- 配置依赖（`torch`, `numpy`, `pytest`, `tqdm` 等）
- 编写最小 `README.md`（运行方式与目录说明）

### A2. 完成五子棋环境
- 实现 `Board`：
  - 15x15 棋盘表示
  - 落子合法性判断
  - 轮到哪方
  - 胜负检测（五连）
  - 和棋检测（棋盘填满）
- 提供可复制状态接口（用于 MCTS 分支扩展）

### A3. 环境测试
- 为胜负判断写核心测试：
  - 横向、纵向、主对角、副对角五连
  - 边界落子情况
  - 非法落子覆盖

**阶段验收标准**
- 命令行可完成一局随机对弈到终局
- 测试通过，胜负判断无明显误判

---

## 阶段 B：模型与推理链路（预计 3-5 天）

### B1. 设计输入输出
- 输入通道建议：
  - 当前方棋子平面
  - 对方棋子平面
  - 当前行动方标记平面
- 输出：
  - `policy`：225 个位置的落子概率
  - `value`：当前局面对当前行动方的胜率（-1 到 1）

### B2. 实现基础 CNN 模型
- 先用轻量网络（6-10 个卷积层）保证可训练
- 输出头拆分为策略头与价值头

### B3. 推理链路打通
- 给定棋盘状态，返回：
  - 所有合法点的先验概率（非法点置零并重归一化）
  - 局面价值估计

**阶段验收标准**
- 单步推理耗时可接受
- 输出维度与数值范围正确

---

## 阶段 C：自对弈训练闭环（预计 1-2 周）

### C1. 实现 MCTS
- 节点统计：`N, W, Q, P`
- 选择策略：PUCT
- 扩展：调用神经网络获取先验与价值
- 回传：沿路径更新统计量
- 根节点加 Dirichlet 噪声（提升探索）

### C2. 自对弈数据生成
- 使用 MCTS 生成每步策略分布（visit count 归一化）
- 保存训练样本：
  - `state`
  - `policy_target`
  - `value_target`（终局结果回填）
- 加入对称增强（旋转/翻转）

### C3. 训练循环
- 损失函数：`policy_loss + value_loss + l2`
- 经验池（滑动窗口）管理样本
- 小批量迭代训练，周期性保存 checkpoint

**阶段验收标准**
- 能连续执行“自对弈 -> 训练 -> 保存模型”流程
- 训练指标（loss）整体可收敛或稳定下降

---

## 阶段 D：评估、模型管理与对战应用（预计 4-7 天）

### D1. 新旧模型对战评估
- 每轮训练后进行固定局数对战
- 统计胜率，超过阈值（例如 55%）才升级为“最佳模型”

### D2. 模型版本管理
- 保留最近 N 个 checkpoint
- 明确 `best_model.pt` 与 `latest_model.pt`
- 记录每轮训练配置、数据量、评估胜率

### D3. 人机对战应用
- 支持用户选执黑/执白
- 支持 AI 思考并落子（可显示思考中状态）
- 对局结束展示胜负并可重开

**阶段验收标准**
- 用户可在应用中完整进行一局人机对战
- 加载指定模型后可稳定响应落子

---

## 阶段 E：优化与发布（持续进行）

### E1. 性能优化
- 调整每步模拟次数（速度/强度平衡）
- 批量推理（如果后期并行自对弈）
- 可选混合精度训练（GPU 场景）

### E2. 强度优化
- 网络深度与宽度调参
- 学习率、温度参数、探索噪声调参
- 开局库或规则先验（可选）

### E3. 工程化
- 增加日志可视化（TensorBoard）
- 增加断点续训
- 提供一键命令：
  - `python -m selfplay.run`
  - `python -m train.run`
  - `python -m app.run`

## 6. 关键超参数初始建议（MVP）

- `board_size = 15`
- `mcts_simulations = 200`（先快后强）
- `c_puct = 1.5`
- `dirichlet_alpha = 0.3`
- `dirichlet_epsilon = 0.25`
- `batch_size = 128`
- `learning_rate = 1e-3`（后期可衰减）
- `replay_buffer_size = 100000`
- `eval_games = 40`
- `promote_threshold = 0.55`

---

## 7. 风险与应对

- 训练太慢：先减小模拟次数和网络规模，保证迭代速度
- AI 强度提升不明显：检查 MCTS 回传、非法点 mask、value 符号是否一致
- 应用延迟高：推理线程化或降低每步模拟数
- 结果不稳定：固定随机种子，记录版本和配置

---

## 8. 最小里程碑（建议按顺序打卡）

1. 规则引擎 + 测试通过
2. 模型前向推理跑通
3. MCTS 单步搜索可落子
4. 自对弈样本生成成功
5. 第一轮训练产出可用模型
6. 新旧模型评估与升级机制可运行
7. 人机对战应用可完整对局

---

## 9. 下一步执行建议

优先启动 **阶段 A**，在 2-4 天内完成“可测试的规则环境”。  
只有规则与胜负判断稳定后，后续 MCTS 与训练结果才可信。
